# Java Collections and File I/O Starter

Coding Homework 3 is a small IT help desk ticket system. You will read ticket
records from CSV, organize them with the Java Collections Framework, and write
a plain-text summary report.

This project uses the same setup as the earlier coding homeworks. One clone
opens directly in **Eclipse**, **VS Code**, or **Cursor** on Windows or macOS.

## What you need

- Git
- JDK 21 or newer
- Eclipse IDE for Java Developers, VS Code, or Cursor

Clone the repository using the URL provided in Canvas. In Eclipse, choose
**File -> New -> Project -> Git -> Projects from Git**. In VS Code or Cursor,
choose **Clone Repository** from the Welcome screen.

## Project layout

```text
src/    Java source files
test/   JUnit tests (the precise assignment specification)
data/   Provided sample CSV file
lib/    JUnit console runner
bin/    Compiled output (generated by your IDE)
```

`Ticket`, `Priority`, `TicketStatus`, and `Main` are complete. Do not add TODOs
to them. Your work is limited to the five methods marked `// TODO` in the four
exercise classes.

## The four exercises

| Class | Task | Main Java ideas |
| --- | --- | --- |
| `TicketCsvReader` | Read `tickets.csv` into ticket objects | `Path`, `Files`, `ArrayList` |
| `TicketQueries` | Find open tickets and unique technicians | `List`, `Set` |
| `TicketStats` | Count tickets by category | `Map`, `getOrDefault` |
| `TicketReportWriter` | Write sorted counts to a text file | `Collections.sort`, `Files.write` |

The CSV format is deliberately simple: five comma-separated fields, no quoted
commas, and a header on the first line.

```text
id,category,priority,status,technician
HD-101,Network,HIGH,OPEN,Maya
HD-102,Password,LOW,CLOSED,Jordan
HD-103,Hardware,MEDIUM,OPEN,
```

An empty technician field means the ticket is unassigned.

## Run the tests

The `test/` folder contains **19 tests across four files**. All 19 fail on a
fresh clone because the five TODO methods are unfinished. That red test run is
your starting point.

- **Eclipse:** right-click `test` or one test class -> **Run As -> JUnit Test**
- **VS Code / Cursor:** use the beaker icon or the run arrow beside a test
- **Terminal:**

```text
java -jar lib/junit-platform-console-standalone-1.14.4.jar execute --class-path bin --scan-class-path --details=tree
```

Work one class at a time: read its `Instructions:` comment, read its matching
test class, implement the TODO, and rerun only those tests until they turn
green. Ordinary loops are enough; streams and lambdas are not required.

## Victory lap

When all 19 tests pass, run `Main`. It reads `data/tickets.csv`, reports the
open-ticket and technician counts, and creates `output/category-summary.txt`.
